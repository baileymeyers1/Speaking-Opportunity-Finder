## 2026-11-04 — Event matcher precision after the production dry run

- The production backfill dry run (1,826 rows: 1,644 events, 130 links, 396 review pairs) auto-linked directory index pages ("Law Conferences in California" → "Medical Conferences in California"), academic titles with the same words and different acronyms ("… Power and Renewable Energy Engineering (PREE)" → "… Renewable Energy and Power Engineering (REPE)"), "Annual Conference" → "CAA Annual Conference", and AWS Student Community Day city editions. - `autoLinkObjection(a, b)` in `eventMatching.ts` gates auto-linking on what the names say, independent of the score: the shorter name's distinctive tokens (no generic, directory or listing words) must all appear in the longer one and must not be empty; every extra token of the longer name must be an acronym it carries or a place one of the rows is in; parenthesised acronyms ("(PREE 2026)", "(EPPC27)", "(G2E)"; "(In-Person)" is not one) must not contradict; the two locations must share a place word (the whole location, since Sessionize writes the venue first; country words do not count). A rejected pair is capped just under 0.80, so it stays in the review band for the admin list. Conference directories (allconferencealert.com, conferenceindex.org, 10times.com, waset.org, …) joined the shared-platform domains.
- `scoreAgainstEvent` scores an event by its editions, by its bare name only when it has none, so the gate sees the city and acronym; with the slug lookup from PR #13, two same-named conferences in different cities (GCBME Los Angeles and Honolulu) become separate events with the organizer-qualified slug.

## 2026-11-03 — Deadlines carry a timezone (roadmap 4)

- **Storage.** `Opportunity.deadlineTimezone` (both schema files): an IANA zone name or `AoE`, null when the page states none. `cfpDeadline` is now the instant the stated day ends in that zone, 23:59:59, with Anywhere on Earth (UTC-12) as the default reading, so a call never shows as closed before it is closed anywhere. Previously it was midnight UTC of the calendar day, which expired the evening before in US zones and twelve hours early for AoE calls.
- **One pure module**, `server/src/lib/deadlines.ts` (21 tests): `endOfDayInZone` / `instantInZone` (Intl-based zone math with a two-pass DST correction, no new dependency), `endOfCalendarDay` for the scrapers' UTC-midnight calendar days, `parseIsoDeadline` for API date-times with an offset (`Etc/GMT±N` fixed-offset zones), `deadlineInstant` (reads a legacy midnight-UTC row with no zone as AoE end of day), `isDeadlinePast`, `daysUntilDeadline`, `formatDeadline` and `describeDeadline` ("closes in 3 days (11:59 PM AoE · Dec 1, 3:59 AM your time)"). The client imports the same file through `client/src/lib/dates.ts`, so card, detail page and API agree on "closed".
- **Extraction** asks for `cfpDeadlineTime` (24-hour) and `deadlineTimezone` (stated only; never inferred from the venue) alongside the date; `parseExtractionOutput` builds the instant, drops zones Intl does not know and falls back to end of day for an unreadable time. `mergeExtraction` closes on the instant and moves the zone together with the deadline it qualifies. Enrichment, verification and live-search writers store the zone; re-scrapes keep the enriched pair.
- **Scrapers.** confs.tech, developers.events, conferencealerts, WikiCFP, javaconferences and both Linkup regex paths read a stated day as AoE end of day; callingallpapers keeps its exact ISO instant and offset; Pretalx uses the event's `timezone` from the API (the CFP page's "Submissions close on" is in that zone); Sessionize reads the exact closing instant it embeds (`data-date="…GMT|-300"`) and stores `Etc/GMT+5`. `parseHumanDate` also accepts `MM/DD/YYYY`. `cleanupExpired` only deletes rows whose deadline passed 36h+ ago, so an unmigrated midnight-UTC row for today survives.
- **Client.** `DeadlineBadge` replaces the inline pill: "3d left" / "Closed" / the closing day in the deadline's own zone, with the closing time in that zone and on the viewer's clock in a tooltip (plus the low-confidence hint, "~" kept). The detail page shows "Monday, November 30, 2026, 11:59 PM AoE · Dec 1, 3:59 AM your time" and notes when the zone was assumed. `isPastDate` / `daysUntil` are gone; saved-page ordering and the save-live payload use the deadline instant and zone. Tests under `TZ=America/Los_Angeles` pin that a deadline "today" in AoE is still open at 11 PM Pacific.
- **Admin catalogue buckets** put the edge between day N and N+1 at noon UTC of N+1, matching the AoE end-of-day instants.
- **Migration** `server/src/scripts/shiftLegacyDeadlines.ts` (`--dry-run` supported, idempotent). Run on the worktree copy of the dev DB: 498 rows with a deadline, 294 stored as midnight UTC without a zone, all 294 rewritten to AoE end of day and stamped `AoE`; 204 rows that already carried a time of day untouched; a second dry run found 0 left. Not run against production.
- Tests: server 245 → 291, client 29 → 48.

## 2026-11-02 — P0 data-integrity fixes in sync and enrichment

- **Re-scrapes no longer wipe enrichment.** `persistResults` built one `data` object for create and update that set `enrichmentStatus/enrichedAt/enrichmentError` to `null`, so every daily sync re-queued every enriched row and overwrote Claude's cleaned title, organization, dates and location. New `scrapers/persistData.ts` builds update data that never includes enrichment bookkeeping and preserves enriched values, filling only gaps. Cross-source dedup no longer overwrites a row's `applyUrl`.
