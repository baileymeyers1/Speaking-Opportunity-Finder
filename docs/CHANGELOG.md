# Changelog

Reverse chronological. Current state lives in `docs/STATUS.md`.

## 2026-11-03 — Speaker profile and explainable match score

- **Profile.** New `SpeakerProfile` model (one per user, cascade delete; both schema files): `topics`, `bio`, `seniority`, `homeCity`, `homeCountry`, `travelRadius`, `remotePreference`, `compensationRequirement`, `preferredFormats`. `GET/PUT /api/profile` (auth required) validated with zod in `services/profileService.ts`; zod is now an explicit server dependency. Client page `/profile` (protected) with a tag input for topics, labelled selects that read their current option's description, a formats fieldset and a live save status; `useProfile` / `useUpdateProfile` hooks; "Profile" in the nav.
- **Match score.** `services/matchScore.ts`: `computeMatchScore(profile, row, now)` is pure and deterministic (no embeddings, no Claude), returning `{ score 0..100, reasons, misses }`. Components: topics 40, location 25, compensation 15, format 10, each counted only when the profile has something to say; 20% quality blend; penalties of 10 / 5 / 3 for a deadline inside 3 days, a low-confidence deadline and an unverified row. `scoreOpportunities` attaches `matchScore` / `matchReasons` / `matchMisses` and sorts best-first with sooner deadline on ties.
- **API.** `GET /api/opportunities` and `/:id` read an optional token; with a profile every stored row and every live result in the response is scored. `sortBy=match` scores up to 500 quality-first candidates in memory and paginates them (a search term ranks all its matches). `opportunityService` lost its inline where/orderBy builders to `services/opportunityQuery.ts` and the controller its query parser to `controllers/opportunityFilters.ts`, both to stay under 300 lines.
- **Client.** `shared/types.ts` gains the profile types, `MatchExplanation`, `sort=match` and the optional match fields on `Opportunity`. Cards show an "N% match" button whose popover lists reasons and misses; the detail page has a "Why this matches" block; the sort select offers "Best match" once a profile exists and `sort=match` round-trips through the URL. Login, register, logout and a profile save drop user-scoped caches. Card header badges now wrap instead of overflowing on phones.
- Tests: server 187 → 209 (match score, profile schema and row parsing); client 28 → 29 (sort=match serialization). Verified in the browser against the worktree API: profile saved and reloaded, cards sorted by match with scores 73/68/68 for a Denver/devops/healthcare profile, popover and detail block rendering.

## 2026-11-03 — Pretalx, Sessionize, non-conference formats, search log

- **Pretalx scraper** (`scrapers/pretalx.ts`, source `pretalx.com`, daily). `GET /api/events/` on pretalx.com (and the self-hosted pretalx.c3voc.de) is a flat public list; the API has no CFP data, so each upcoming event's public `/{slug}/cfp` page is fetched (8 in flight). Open/closed comes from the submit button, the deadline from the status line, which Pretalx renders in the event's locale (`2026-11-11`, `2026/11/15`, `28.02.2027` all seen live). Custom-domain redirects become the applyUrl. Live: 83 upcoming events, 39 open calls, 3.5s; 8 of the 39 have no deadline set in Pretalx. Fixtures: the event list, eight CFP pages (open, not yet open, closed, no deadline, Japanese, German).
- **Sessionize scraper** (`scrapers/sessionize.ts`, source `sessionize.com`, daily). The Discover listing redirects to login, so the scraper reads `sitemap/events.xml` (11,059 public event pages, newest first; robots.txt only disallows `/app/`) and the newest 80 pages per run. Each page gives call open/close dates, event date or planned dates, location, website and description; recurring user groups are stored as `meetup`. Live: 80 pages, 74 open calls (56 conference, 18 meetup), 3.0s.
- **Format-aware Linkup queries.** The query list moved to `scrapers/linkupQueries.ts`; every entry carries a `format`. New group: 8 podcast guest-call queries, 6 meetup/user-group, 4 webinar, 3 panel (110 queries total, the rotation adjusts). CFP indicators recognise "podcast guest", "speakers wanted", "lightning talk", "call for panelists". `OpportunityFormat` already covered these values in `shared/types.ts`, `extraction.ts` and the client filter; no type change was needed. Luma and Meetup.com were not added (decided 2026-11-03).
- **Search log and query promotion.** New `SearchLog` model (both schema files). `recordSearch` is awaited by both live-search controllers; the opportunities routes take `optionalAuthMiddleware` so a signed-in user's id is recorded. `promotedLinkupQueries(limit)` returns the most frequent normalized queries of the last 30 days (at least two searches, not already in the static set), and the daily Linkup run appends up to 2 of them after its 6-query slice. `GET /api/admin/analytics/search-log` returns 7/30-day totals and top queries.
- `pretalx.com` and `sessionize.com` join `TRUSTED_SOURCES`. Server tests 187 → 223 (Pretalx, Sessionize, Linkup query set, search log).

## 2026-11-02 — Client data flow: URL filters, TanStack Query, file splits, lint

- **The URL is the only filter state.** `client/src/filters/serialize.ts` serializes every filter (search, industries, locations, format, remote, compensation type/min/max, quality, sort, page) to search params and back, with round-trip tests. Home reads filters from `useSearchParams` only; FilterPanel writes to the URL and debounces typed text in `useSearchDraft`, flushing before Live Search so a click inside the debounce window never searches the previous term. The three ad-hoc serializers in Home are gone.
- **TanStack Query owns fetching and caching.** `@tanstack/react-query` with the persist plugin and a localStorage persister (public lists and filter options only, 24h, `v2` buster) keeps the instant cold-start render. Hooks in `client/src/hooks/`: `useOpportunities` (keyed on the serialized filters, aborted via the query signal on key change), `useLiveSearch` (a mutation that cancels the in-flight DB fetch and writes the merged result into the list entry for the same key), `useFilterOptions`, `useSaveOpportunity` (one save-live-then-save flow for card and detail, which also swaps the live item for the stored row in every cached list), `useOpportunity` (detail seeded from the list that linked to it; live ids resolve from the cache), `useSavedOpportunities`, `useSavedSearches`, `useAdminAnalytics`. Back navigation restores the exact prior list (same URL = same key); changing a filter refetches even while live results show. Removed `cachedOpportunities`, the sessionStorage live cache, `skipNextFetch`, `allLiveResults` and `utils/liveResultsCache.ts`; legacy storage keys are removed on load.
- **Files split under ~300 lines.** Home → Home + OpportunityGrid + LiveSearchBanner; FilterPanel → SearchBar, ActiveFilterPills, AdvancedFilters; AdminDashboard → one component per card in `components/admin/` plus `admin/types.ts`; OpportunityCard and OpportunityDetail shed date/badge helpers (`lib/dates.ts`, `lib/opportunityDisplay.ts`), save controls and the detail skeleton; the "Verified Xd ago" and approximate-date tooltips both pages render live in `components/VerificationHints.tsx`.
- **Shared wire types.** `shared/types.ts` is now what crosses the wire (string dates; `OpportunityBase<Date>` for server code before serialization) with `isClosed`, `isRelevant`, `matchesLocationFilter`, `isLiveResult`, `liveSearchUrl`, `isAdmin`, `compensationAmount`. The client re-exports it; `opportunitiesController` types every response payload.
- **Bugs fixed.** Admin dashboard waited on nothing and bounced a reload to `/login`; saved-page tab counts came from a server-filtered list; UTC-midnight dates rendered a day early (now formatted with `timeZone: 'UTC'`, tests run under `TZ=America/Los_Angeles`); collapsed advanced filters stayed tabbable (now `inert` + `aria-hidden`); the Sort select had no accessible name; auth-page card titles had no heading semantics.
- **Server rate limiting.** `authLimiter` (10/15 min) was mounted on all of `/api/auth` including `/auth/me`, which runs on every page load, so ~10 page loads locked a user out of login. It now wraps only the credential routes, and all limiters are skipped in development.
- **Lint and tests.** ESLint 9 flat config at the root (`typescript-eslint`, `react-hooks` v7, `jsx-a11y`); `npm run lint` passes across client, server, shared and e2e. New `e2e/live-search.spec.ts` mocks `/api/opportunities` and asserts the merge / back / filter-change flow. Client unit tests: 2 → 21.

## 2026-11-02 — Verified listings, one structured extraction, fast live search

- **One extraction module.** `services/extraction.ts` owns the single Claude call: structured outputs (`output_config.format` with a strict JSON schema; verified against the API on `claude-haiku-5-5` with SDK 0.74) return `{ eventDate, cfpDeadline, location, isRemote, isClosed, isRelevant, compensationType, compensationAmount, format, industries, cleanTitle, cleanOrganization, confidence }`. The prompt includes today's date; the text block is found with `find`; `stop_reason` is checked. `mergeExtraction` is the one set of merge rules (extracted values overwrite, nulls keep existing, a past deadline closes the row, confidence is exposed). Replaces `buildEnrichmentPrompt`/`parseEnrichmentResponse` and `extractMetadataWithClaude`/`mergeClaudeMetadata` and their regex JSON parsing; live results carry `isClosed`/`isRelevant` instead of a fake 2020 deadline.
- **Page fetch in the worker.** `services/pageText.ts` (shared with live search) fetches `applyUrl` with an 8s timeout and returns 5000 chars of visible text. The worker extracts from the page; a 404/410 marks `isClosed` without a Claude call; a short description no longer skips a row whose page was fetched. `processNextBatch` takes a time budget (50s from the cron).
- **Scheduled verification.** New columns `verifiedAt`, `verificationError`, `dateConfidence` (both schema files). When no unenriched rows remain, the enrichment cron re-verifies: deadlines within 14 days not checked in 2 days, then any visible row not checked in 7 days. Reuses the page fetch + extraction, updates dates/location/`isClosed`, counts against the same daily budget. Enrichment from a fetched page also stamps `verifiedAt`. `services/verification.ts` holds the windows, candidate queries and update builders.
- **Live search returns fast.** Dedupe by URL before any enrichment, one Linkup page per variant, top 8 enriched synchronously, every hit persisted in the request (`source: 'Live Search'`, unenriched ones with `enrichmentStatus: null`). The fire-and-forget `autoSaveLiveResults` second Claude pass is gone from both controller call sites. Measured live: 15 results in 10.6s.
- **Client.** "Verified Xd ago" on `OpportunityCard` and `OpportunityDetail`; low-confidence dates render as "~Dec 1, 2026" with a tooltip. Types gain `verifiedAt`, `verificationError`, `dateConfidence`, `isClosed`.
- Tests: server 159 → 187 (extraction, pageText, enrichment plan, verification, live persistence); client +8. Removed the regex-parsing tests they replace.

## 2026-11-02 — Ingestion consolidated; Vercel settled as the deploy target

- **Scraper registry and per-scraper runs.** `scrapers/index.ts` now holds a `SCRAPERS` registry (name, cadence, run). `syncOpportunities(mode, { timeBudgetMs, only })` runs sources least-recently-run first, wraps each in a timeout, persists each scraper's rows before starting the next, and records every run in a new `ScraperRun` table. Cron routes pass a 50s budget to fit Vercel's 60s limit; the admin sync route accepts `?scraper=name`. New `GET /api/admin/analytics/scraper-runs`.
- **Linkup runs a rotating slice.** `scrapeLinkupCFPs(apiKey, { offset, maxQueries })`; the daily run takes 6 of the ~90 queries by date rotation instead of all of them sequentially.
- **Dead scrapers removed:** eventbrite (endpoint retired), linkedinEvents (stub), airtableEvents (never configured), usMegaEvents / pacEvents / prNewsOnline (returned 0 rows by construction and were not CFP sources), papercall (domain no longer resolves). conferenceAlerts, developersEvents and wikicfp repaired with a shared `scrapers/lib/html.ts` and fixture tests.
- **URL normalization keeps identifying query params** and strips only tracking ones, sorted; WikiCFP rows no longer collapse to one record.
- **Quality rescoring is scoped** to rows touched by the run instead of the whole table on every sync.
- **One Prisma client** (`server/src/lib/prisma.ts`) replaces eleven per-module instances.
- **Search is case-insensitive on Postgres** (`mode: 'insensitive'`), and the industry filter matches the quoted JSON token so "ai" no longer matches "retail".
- **Vercel is the only deploy target.** `render.yaml` deleted; CLAUDE.md and README rewritten for Vercel; root planning docs moved to `docs/archive/`. The build command now runs `prisma db push`.
- Year constants computed at call time in confstech, linkupcfp and liveSearchService.

## 2026-11-02 — P0 data-integrity fixes in sync and enrichment

- **Re-scrapes no longer wipe enrichment.** `persistResults` built one `data` object for create and update that set `enrichmentStatus/enrichedAt/enrichmentError` to `null`, so every daily sync re-queued every enriched row and overwrote Claude's cleaned title, organization, dates and location. New `scrapers/persistData.ts` builds update data that never includes enrichment bookkeeping and preserves enriched values, filling only gaps. Cross-source dedup no longer overwrites a row's `applyUrl`.
- **Cleanup no longer deletes saved rows.** `cleanupExpired` excluded nothing; on Postgres the cascade removed users' `SavedOpportunity` rows, on SQLite it threw and aborted the sync. Both delete queries now require `savedBy: { none: {} }`.
- **Closed / irrelevant flags persist.** Enrichment used to set `qualityScore: 0`, which `recalculateAllQualityScores` undid on the next sync. Added `isClosed` and `isRelevant` columns; `computeQualityScore` returns 0 when either is set; browse filters on them explicitly.
- **Enrichment budget and locking moved to the DB.** New `EnrichmentUsage` table (per UTC day) and `enrichmentClaimedAt` / `enrichmentAttempts` columns. Slots are reserved before the API call (failures are billed too); rows are claimed with an optimistic update; failed attempts retry up to 3 times before being marked `failed`. New module `services/enrichmentBudget.ts`.
- **Claude call fixes.** Default model `claude-haiku-4-5-20251001` → `claude-haiku-5-5` (10x cheaper per token); `max_tokens` 256 → 2048 with `stop_reason === 'max_tokens'` treated as a retryable failure; the text block is located with `find` instead of `content[0]` (which may be a thinking block on current models); `output_config.effort: 'low'`; client gets `timeout` and `maxRetries`; prompt includes today's date and computed example years.
- Moved `ScraperResult` and `computeQualityScore` to `scrapers/qualityScore.ts` (re-exported from `scrapers/index.ts`). Dev Prisma schema aligned with production (cascades, `compensationType` index).
- Tests: +18 (persistData merge rules, quality flags, budget helpers); removed a placeholder test that tested `Date.toDateString`.
